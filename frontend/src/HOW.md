> We write about HOW the project works here.

TL;DR: We use a machine learnig model to represent video metadata as vectors in a high-dimensional vector space. We then project that space to low dimension for visualisation and clustering, using another model. We finally use a clustering algorithm to classify semantically similar neighbors into a single category. The last step was done manually here.

At its core, magpie uses a machine learning model trained on my own "watch later" playlist's videos. The first step is to take each video from the playlist and "clean" it so that future steps have a higher signal to noise ratio. We then need to make sure that the data being fed to the transformer is as _relevant_ to the video content as possible, as that would decide what the output of the transformer looks like. 

The next step is to map this clean data to a vector space, in order to generate something called a _embedding_. Words can be thought of as a vector of floats. Two vectors that are close to each other in that vector space have some semantic similarity. Here we use a metric called _cosine similarity_, which measures the angle between two vectors. Thus two words are similar if they are used in similar contexts. This idea generalises well to sentences and paragraphs too, which is exactly what we are dealing with here. 

I have used the Sentence-Transformers library here, in particular, the `all-MiniLM-L6-v2` model. This model specifically generates a 384-dimension vector which is learnable by a neural net - that is what produces the contextualized embeddings. Here the relevance of the data is of most importance, as by default, input text longer than 256 word pieces is truncated. The sentence vector produced can now be used for an operation called _clustering_, which is essentially a grouping of similar things.

Before we do that though, we need to perform _dimensionality reduction_ on these embeddings. This is done so that we get a low-dimensional representation that retains some meaningful properties of the original data. Why can't we work in the high-dimension space itself? Essentially, when dimensionality increases, the volume of the vector space increases so fast that the available data becomes sparse and semantically valuable context is lost. Also, organising data in this space is undesirable as all objects appear to be sparse and dissimilar in many ways, which prevents common data organisation stratgies. Thus, there is a need for dimensionality reduction. I have used the UMAP model here which projects the high-dimensional vectors into a low, two-dimensional space. 

We now turn our attention to the problem at hand itself - clustering. I chose the HDBSCAN algorithm for this job. I did that because it was heirarchal and density-based.Using something like k-means would've meant guessing the number of categories myself, which is something I did not want to do. HDBSCAN also pairs nicely with UMAP, and Sentence-Transformers to UMAP to HDBSCAN is quite the popular pipeline for content categorisation tasks. I also used the `cosine` metric for HDBSCAN, so that it uses cosine similarity to find out the semantic similarity between two sentence vectors. Now comes human intervention. Or, if you're feeling brave today, you could use LLMs for this. But I wanted to do this myself. The next step indeed is to look at all the clusters and find some connected links between them, in order to give it a name. For exmaple, you spot a neighborhood of dots, all of which seem like they belong to the 'Horror' cluster. Then you simply assign that label to that cluster, and call it a day. That is the simplest form of content categorisation and is what I did here. One could also go one step beyond and train a classifier based on those labels provided earlier, but that is something that I didn't do here, mostly because I didn't want to.
